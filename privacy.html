Privacy Policy

Last updated: 2026-09-28
Operator: VegaNec Studio

1. Scope

This notice describes the current Studio Publisher desktop app and this documentation website. The app is operated for its owner's own connected Etsy and Pinterest accounts. It is not currently offered as a service for other people's accounts.

2. Information processed

  • Developer-app identifiers and secrets; OAuth authorization codes, access/refresh tokens, permissions, expiry information and temporary media-upload authorizations.
  • Connected account/shop identifiers, Pinterest username and account type, owned-board information, shop currency and relevant readiness metadata. API responses may include additional profile/shop fields; selected fields support the requested operation rather than a general profile database.
  • Selected product descriptions, prices, quantities, tags, accessibility text, links, digital-product files, images and videos that the operator chooses for a release.
  • Local file names/paths and hashes, approval records, timestamps, remote resource identifiers, request-result metadata and error records used to verify or resume operations.
  • The optional website-setup helper processes the operator's chosen public name/contact, GitHub account and repository identifiers, approved public-page content and publication records.
  • Requested aggregate Pin impressions, saves and outbound clicks. These are not individual viewer identities, customer orders, purchase histories or a measure of unique product visitors.

The current workflow does not request Pinterest/Etsy account passwords, read personal browser profiles, export session cookies, or request buyer-email, checkout, card or customer-order permissions.

3. Purposes and account control

Data supports OAuth authentication, confirmation of the intended account and destination, specifically approved publishing, duplicate-submission safeguards, failure recovery and requested aggregate metrics. Account access begins through the operator's platform authorization. The current app has no built-in audience-advertising, customer-messaging, third-party telemetry or AI-training data-transfer feature. The operator should not include secrets or unnecessary personal information in publishing content.

4. Recipients and publication

Connection requests and selected API operations go to Etsy or Pinterest. Approved listing files are uploaded to Etsy. Approved Pin content goes to Pinterest; video bytes and the provider's temporary upload form go to Pinterest's designated upload service. API credentials are not forwarded to that media-upload host. The app does not upload the entire local workspace or sell account data.

The optional website-setup helper uses GitHub sign-in through the existing Git Credential Manager. After a separate exact-page confirmation, it sends only the public homepage, this policy, a static-site marker and necessary repository metadata to GitHub. It does not upload the private app or product files.

Approved published content may become visible to others according to the platform's settings and access tier. Local drafts are not publication. Each platform applies its own terms and privacy practices. See Pinterest's privacy policy and Etsy's privacy policy.

5. Local storage and security

The desktop app runs on the operator's Windows computer. Etsy/Pinterest app secrets, OAuth tokens, temporary upload forms and batch approvals are protected with Windows CurrentUser Data Protection API encryption and decrypted in memory when used. Campaign files, media, reports, metrics and the operation journal are ordinary local files and are not all encrypted by this app. Upload snapshots may temporarily use disk. The operator manages device security, file permissions and backups. No protection is risk-free.

GitHub credentials are managed by the existing Git Credential Manager according to its configured credential store. The website helper retrieves a credential into memory for the approved GitHub API operation; it does not save an additional plaintext token file, display the credential in chat, or include it in the published repository.

6. Retention, revocation and deletion

The current app has no automatic retention/deletion schedule for its local operational files. Its stored credentials and records remain until the operator deliberately removes or replaces them; provider expiry and Credential Manager's own behavior also apply. Closing temporary upload snapshots is not a guarantee of secure erasure or backup deletion.

The operator can stop the app, cancel a current batch approval and revoke platform authorization using the relevant provider's account controls. Cancellation cannot recall a request already sent. Revocation does not automatically erase local files or delete platform-held content. Pending or uncertain writes should be reconciled before execution history is removed, because that history helps prevent duplicates. Platform-held records and published content must be managed through the platform.

Following links to other services is subject to those services' own practices.
